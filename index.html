02 / From first question to final review

No mystery between
the brief and the handover.

Agree what good looks like before the work starts. Check against it before calling the work finished.

  1. Scope

    We define the problem, the systems involved, deliverables and acceptance criteria.

  2. Agree

    We confirm scope and timing in writing. Security testing requires the system owner's explicit authorisation.

  3. Execute

    We build the agreed solution or carry out security testing, with progress shared along the way.

  4. Verify

    Development is checked against acceptance criteria. Security findings include evidence, priorities and fixes.

  5. Hand over

    You receive the agreed code, documentation or report. Follow-up support and retesting are scoped together.

03 / A firm boundary

Authorised work.
And nothing else.

We only test systems the client owns. If you can't authorise testing of a system, we won't test it.

  • Every engagement has a written agreement.
  • The owner of each system gives explicit authorisation.
  • Nothing outside the agreed scope is tested.
  • Findings are shared only with the client.
